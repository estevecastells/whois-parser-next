# WHOIS parser audit, DNS Magnitude ranks 176-200

Date: 2026-09-19

## Scope and ordering

This audit follows the ICANN DNS Magnitude snapshot for 2026-09-12,
generated 2026-09-18. The source is the public [ICANN DNS Magnitude
table](https://magnitude.research.icann.org/). Ranks retain the source table's
daily-rank positions and are not a claim about registration volume.

The live checks used `google.<tld>` as the registered probe where that path
was available and a generated `zz176200-<tld>-20260919.<tld>` label for the
absence probe. Captured responses were reduced to the fields needed by the
parser and contact values were removed or replaced with `REDACTED`.

## Parser changes

The focused fixes are deliberately limited to observed response formats:

- `.ac` recognizes the current `Domain not found.` absence marker.
- The Afilias scanner does not treat a key/value record header as a
  disclaimer and stops at its `Last update of WHOIS database` footer. This
  preserves the first registry record when a registrar referral is appended.
- `.dz` parses the current compact `Domain Name:` and `% No match for domain`
  responses.
- `.cm` accepts the current `active https://icann.org/epp#active` status,
  current field labels, nameservers, and exact no-object response.
- CentralNic parsers recognize the current `.space` availability sentence.
- `.click` treats the explicit unsupported-interface response as unavailable.
- `.mw` uses a small `BaseWhoisd` adapter for the current status-less record
  format.

## Verification

The dedicated suite in `spec/whois/parsers/topdomains_176_200_spec.rb` has 17
examples and 0 failures. It covers registered and generated-absence fixtures
for `.om`, `.ac`, `.vc`, `.space`, `.ag`, `.cm`, and `.mw`, plus the `.dz`
field normalization and `.click` denial contract.
