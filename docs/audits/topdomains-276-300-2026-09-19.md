# WHOIS parser audit, DNS Magnitude ranks 276-300

Date: 2026-09-19

## Scope and source

This is a point-in-time port-43 WHOIS audit for the entries at daily ranks
276 through 300 in the [ICANN DNS Magnitude snapshot](https://magnitude.research.icann.org/)
for 2026-09-12, generated 2026-09-18. The rank is the snapshot's daily usage
ordering, not a claim about registration volume. The `.server` entry is marked
undelegated by the source and is retained for completeness.

The registered probe was `google.<tld>` where the endpoint answered. The
absence probe was a generated, syntactically valid label of the form
`codex276-<tld>-20260919.<tld>`. Captures were reduced to the fields needed by
the parser, with contact values and service disclaimers removed.

## Safety decisions

The audit does not infer availability from an empty, unresolved, undelegated,
unsupported, or registry-denial response. Identity Digital and Tucows denial
messages are represented as unavailable responses, so callers cannot mistake
them for either a registration or an available name. `.ovh` is the only new
parser whose generated absence response is a bare error-style line; it is
scoped to the OVH host and covered by a registered fixture, avoiding a generic
`404` heuristic.

The CentralNic parser remains the shared implementation for the `.art`,
`.best`, and `.cfd` hosts. The `.win` endpoint currently has the same field and
absence layout as `.design`, so its host adapter reuses that parser rather than
duplicating the response rules.
