# WHOIS parser audit

Date: 2026-09-19

## Scope

This was a live, point-in-time audit of port-43 WHOIS parsing. We tested one
registered domain and one likely-unregistered domain for each TLD in the union
of the [DNIB Q2 2026](https://www.dnib.com/articles/the-domain-name-industry-brief-q2-2026)
top overall, top ccTLD, and top gTLD lists:

`.com`, `.cn`, `.de`, `.net`, `.org`, `.uk`, `.xyz`, `.ru`, `.top`, `.nl`,
`.br`, `.fr`, `.au`, `.in`, `.eu`, `.info`, `.shop`, `.online`, `.store`,
`.vip`.

A likely-unregistered test input represents an expectation for the test case.
It is not authoritative proof that a domain is available.

## Results

| TLD | Observed result |
|---|---|
| `.com` | Good behavior for both registered and likely-unregistered cases |
| `.cn` | Partial: the likely-unregistered case returned an error |
| `.de` | Partial: the registered response produced a parse error |
| `.net` | Good behavior for both cases |
| `.org` | Partial: the likely-unregistered response produced a parse error |
| `.uk` | Good behavior for both cases |
| `.xyz` | Broken: the likely-unregistered case was falsely classified as registered |
| `.ru` | Good behavior for both cases |
| `.top` | Parser unavailable for the current server format |
| `.nl` | Unsafe: a rate-limit response was falsely treated as available; registered metadata was sparse |
| `.br` | Good behavior for both cases |
| `.fr` | Broken: the likely-unregistered case was falsely classified as registered |
| `.au` | Parser unavailable for the current server format |
| `.in` | Parser unavailable for the current server format |
| `.eu` | Good behavior for both cases |
| `.info` | The old endpoint reported that the TLD is not supported |
| `.shop` | WHOIS was retired on 2026-05-01 in favor of RDAP |
| `.online` | Parser unavailable for the current server format |
| `.store` | Parser unavailable for the current server format |
| `.vip` | Parser unavailable for the current server format |

## Interpretation

The existing parser handles six of the 20 TLDs correctly for both test cases.
It has meaningful gaps for current registry formats and ambiguous responses.
Errors, rate-limit responses, retired WHOIS services, and unsupported formats
must not be converted into positive or negative availability claims.

These results are a point-in-time port-43 parser audit, not an availability
guarantee. WHOIS services and registry formats can change without notice. RDAP
should be preferred where the registry has retired or replaced WHOIS.
