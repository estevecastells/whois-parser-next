# WHOIS parser audit, DNS Magnitude ranks 251-275

Date: 2026-09-19

## Scope and source

This is a point-in-time port-43 WHOIS audit for daily ranks 251 through 275
in the [ICANN DNS Magnitude snapshot](https://magnitude.research.icann.org/)
for 2026-09-12, generated 2026-09-18. The source rank is retained below,
including delegated domains that do not expose public port-43 WHOIS. These
results describe the observed endpoint and parser behavior, not a guarantee
that every name can be registered.

The `.sr` row below reflects the 2026-09-19 audit. A later parser-only
follow-up verified the current IANA-listed host on 2026-09-25; see the
[`.sr` current-host follow-up](topdomains-251-275-sr-followup-2026-09-25.md).
That parser addition does not establish default-client routing or effective
coverage.

Registered fixtures use `google.<tld>` where that was a current registry
record, except `.gi`, which uses the current `nic.gi` record because common
brand probes were GlobalBlock policy responses. `.fo` uses `google.fo`.
Absent fixtures use a generated syntactically valid label where the registry
returned an authoritative absence. The `.dm` generated label was rejected as
a restricted word, so it is deliberately not treated as an absence fixture.
Captures were reduced to fields needed to reproduce status, dates, and
nameserver parsing. Contact data and registry policy text were removed.

## Safety decisions

Web-only mappings, no-adapter mappings, reserved names, restricted names,
GlobalBlock policy responses, and explicit unsupported-TLD notices are not
registration or availability evidence. The new unsupported-registry adapters
raise `Whois::ResponseIsUnavailable` for the explicit denial, while the
`.work` reservation response remains `:unknown`. No denial, restriction, or
unknown result is mapped to `:registered` or `:available`.

The `.nf` endpoint omits `Domain Status` for an authoritative no-object
response, so its host parser recognizes the exact `No Object Found` marker.
The `.ink` and `.icu` endpoints expose standard ICANN records with different
absence lines, and `.fo` has moved from a historical whoisd response to an
ICANN-style response. The `.fo` adapter normalizes only the observed fields
and retains the old parser contract and fixtures.
