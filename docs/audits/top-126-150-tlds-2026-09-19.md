# WHOIS parser DNS Magnitude ranks 126-150 audit

Date: 2026-09-19

## Scope and source

This is the next verified range after the Top 100 audit. The ordering is the
ICANN DNS Magnitude snapshot for 2026-09-12, generated 2026-09-18, with the
same delegated, special-use, and undelegated rows retained. The source table
is available at <https://magnitude.research.icann.org/>.

The audit checks current hostname mapping, the actual port-43 response where a
server answered, and the parser result. A denial, refusal, timeout, unsupported
TLD, web-only path, or malformed response is not availability evidence.

## Changes in this range

- Added current-response coverage for `.hn`, `.tn`, `.by`, and `.ve`.
- Added denial and unknown-response guards for `.li`, `.ir`, `.lu`, and `.nu`.
- Added `.host` mapping and an ICANN-compliant parser for its port-43
  availability and registration responses.
- Replaced the stale web-only `.cr` mapping with `whois.nic.cr` and added a
  parser for its current port-43 format.
- The fixtures under
  `spec/fixtures/responses/audit-126-150-2026-09-19/` contain only the
  classification-bearing lines from real responses. Timestamps, contact data,
  and policy text were removed.

Unknown, denial, throttle, timeout, and unsupported responses remain distinct
from `:available` and `:registered`.

## Follow-up evidence, 2026-09-25

Two higher-priority gaps in this range were rechecked against the WHOIS hosts
listed in IANA's current delegation records. The `.ma` mapping already used
IANA's `whois.registre.ma` host, but its parser recognized only an older
rwhois response shape. The current registered response is:

```text
Domain Name: google.ma
Domain Status: clientTransferProhibited https://icann.org/epp#clientTransferProhibited
```

A generated `.ma` query returned the exact no-object marker below (with the
query name echoed in the response):

```text
Domain Name: codex-audit-20260925-ma131.ma
The queried object does not exist: No Object Found
```

The `.ma` parser now requires the observed EPP status and a single `.ma`
domain name for this current registered shape; a bare name or other status
stays unknown. It recognizes the exact no-object line only when no status or
conflicting record fields appear, while retaining the older explicit rwhois
fixtures.

The `.hn` audit previously retained current absence but not current
registration evidence. A bounded query to IANA's `whois.nic.hn` returned the
following record markers:

```text
Domain Name: google.hn
Domain Status: active https://icann.org/epp#active
Domain Status: clientTransferProhibited https://icann.org/epp#clientTransferProhibited
```

A generated `.hn` query returned `Domain Name: codex-audit-20260925-hn129.hn`
and the exact `The queried object does not exist: No Object Found` marker.
The current registered response previously failed parsing because its Spanish
registry footer was not recognized by the shared CoCCA2 scanner. The scanner
now treats the observed `Queda absolutamente prohibido su uso` prefix as a
footer, and the `.hn` parser leaves a no-object marker combined with record
status fields unknown. After that scanner fix, the live registered response
parses as `:registered`, and the generated-name response as `:available`.

Both TLDs already resolve through `whois` 6.0.3's standard port-43 adapter to
the same hosts IANA lists; no routing override is required for these parser
classes. Fixtures retain only the queried domain, classification-bearing
status lines, and the minimal `.hn` footer prefix; contact fields and other
personal data were removed. Adversarial specs cover empty, denied,
rate-limited, status-only, and conflicting replies. Probe bounds were a
4-second connection timeout, 7-second total deadline, 64 KiB response cap,
and at least 2 seconds between queries. Repeated queries were limited to the
two named examples while extracting and confirming sanitized result markers.
